## 수평 반동이 없음

현재 반동 주문의 `pattern`, `horizontal`, 수평 범위부터 확인합니다.

```yaml
recoil: 0.5
horizontal: 1.5
pattern: vertical
```

이 조합은 기본 bias·범위에서 **yaw 0°**입니다. vertical의 수평 계수 0에 `1.5 × 0.5`를 곱해도 0입니다. 첫 발부터 무작위 수평을 원하면 다음처럼 바꿉니다.

```yaml
recoil: 0.5
vertical: 1.0
horizontal: 1.5
pattern: random
vertical-min: 1.0
vertical-max: 1.0
horizontal-min: -1.0
horizontal-max: 1.0
growth: 0.0
```

위쪽 0.5°, 좌우 -0.75°..+0.75°가 발당 계산값입니다. `recoil: 0`, `horizontal: 0`, 수평 min/max 모두 0, custom의 수평 0 점도 확인하세요. YAML 변경 뒤 `/ms reload`와 콘솔 오류 확인이 필요합니다.

## 단발·점사에서만 수평이 없음

기본 valorant은 첫 **4발 수평 0**, 5발째부터 흔들립니다. 기본 `reset-delay: 400`에서 발사 간격이 400ms 이상이면 매번 첫 발로 초기화됩니다. 짧은 점사를 반복하면 수평 구간에 도달하지 않을 수 있습니다.

의도한 동작이 단발 수평이면 random 또는 수평 값이 있는 custom을 선택합니다. 연사 패턴을 더 오래 유지하려는 경우에는 실제 발사 간격과 초기화 간격을 함께 조정합니다. [패턴 규칙](recoil-logic.md#패턴별-수평-반동)을 참고하세요.

## 반동 전체가 없음

1. Paper 1.21.11 / Java 21 / 공식 MagicSpells Beta 18인지 확인합니다.
2. 애드온 JAR이 `plugins/`에 한 개만 있는지, 전체 `spell-class`가 정확한지 확인합니다.
3. 시작 또는 `/ms reload` 콘솔에서 해당 주문의 설정 오류를 확인합니다. 숫자를 따옴표로 감싸거나 범위를 벗어나면 거부됩니다.
4. [빠른 시작의 최소 주문](getting-started.md#2-플러그인과-최소-주문-설치)을 성공 확인 옵션 없이 콘솔에서 시험합니다.
5. 관리자 권한으로 `/magicrecoil status`의 패킷 수를 시전 전후 비교합니다. 반동이 끝나면 active players가 0이 되는 것은 정상입니다.

## 총기에 연결하면 반동이 없음

발사 목록과 성공 확인의 이름을 나란히 확인합니다.

```yaml
spells:
  - MyGun_Beam
  - MyGun_Recoil
```

반동 주문에는 `require-success-of: MyGun_Beam`이 필요합니다. 실제 발사는 Beam인데 참조가 `MyGun_PP`라면 반동 전체가 거부됩니다. 두 호출은 같은 틱에 연속 실행되어야 하고 성공 기록은 한 번만 소비됩니다. direct/delayed 호출이 성공 이벤트를 제공하는지도 [연동 가이드](integration.md#호출-방식별-주의점)에서 확인하세요.

## 중앙과 오른쪽으로만 반복하거나 계속 상승함

0.1.0-alpha.3 이상 내장 valorant를 사용합니다. 이전 코드는 sin 값을 매 발 더해 한쪽으로 치우친 누적 위치를 만들었습니다. 현재는 목표 위치의 차이로 중앙 양쪽을 통과합니다. 양수 horizontal-bias, 비대칭 수평 범위, 잡음, 강한 클리핑이 있으면 의도적으로 편향될 수 있습니다.

상승 제한은 valorant-max-rise 각도이며 발 수가 아닙니다. 발사 간격이 reset-delay 이상이거나 세션을 반복 초기화하면 매번 새 상승이 시작됩니다. pattern: vertical은 이 상한을 사용하지 않습니다. [현재 계산 규칙](recoil-logic.md#내장-valorant의-상한과-좌우-중심)을 확인하세요.

## 강도가 예상과 다름

- `recoil`은 기본 강도, `vertical`과 `horizontal`은 배율, min/max는 계수 범위입니다. 주석은 동작을 바꾸지 않습니다.
- random의 기본 수직 범위는 0..2입니다. 일정한 상승을 원하면 수직 min/max를 1로 고정합니다.
- `growth`가 0보다 크면 연사 강도가 증가합니다. `max-recoil`은 두 축의 합성 길이를 제한하므로 한 축만 크게 올려도 다른 축의 실제 각도가 줄어들 수 있습니다.
- 위·아래 시점 한계에서는 pitch가 잘립니다. 수평 범위가 0을 포함한 random은 작은 값이나 같은 방향이 연속으로 나올 수 있습니다.

계산 순서는 [반동 로직](recoil-logic.md), 허용 범위는 [설정 표](configuration.md)에 있습니다.

## 반동이 느리거나 중지되지 않음

`recoil-steps`가 있으면 smoothness보다 우선합니다. 우선 2~3틱으로 확인하고 TPS도 살펴보세요. 사격 중단만으로는 남은 반동을 취소하지 않습니다. 재장전 시작은 `stop-on-spells`, 사격 버프 종료는 `stop-on-buff-end`에 실제 이름을 연결합니다.

`reset-delay`는 시점을 되돌리는 옵션이 아닙니다. 자동 복귀가 필요하지 않으면 `auto-return: false`를 유지하세요. 즉시 초기화는 `/magicrecoil reset PlayerName` 또는 StopRecoilSpell을 사용합니다.

## 탄환 방향이나 탄퍼짐이 다름

`beam-horizontal-spread`, `projectile-horizontal-spread`는 발사체의 퍼짐이며 시점 yaw가 아닙니다. 현재 탄환은 먼저 발사되고 새 반동은 그 뒤 적용됩니다. 반복 주문이 예전 위치·방향을 저장했다면 후속 탄환이 현재 조준을 사용하지 않을 수도 있습니다. [탄환 방향과 호출 순서](integration.md#탄환-방향과-호출-순서)를 확인하세요.

## 재현 내용을 남길 때

서버·Java·MagicSpells·애드온 버전, 가장 작은 관련 YAML, 실행한 순서, 콘솔 오류, TPS·지연, 다른 시점/안티치트 플러그인 유무를 기록합니다. 암호·토큰·개인 플레이어 데이터와 전체 운영 서버 폴더는 첨부하지 마세요.

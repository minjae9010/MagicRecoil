## 한 발이 시점에 적용되는 순서

1. 기존 총기의 탄약·재장전 조건을 통과한 발사 분기에서 발사체 주문을 실행합니다.
2. 바로 다음에 같은 틱에서 `RecoilSpell`을 호출합니다. `require-success-of`가 있으면 해당 주문의 성공 기록을 한 번 소비합니다. 여기서 성공은 **발사 주문 실행 성공**이며 탄환 명중 여부가 아닙니다.
3. 플레이어의 현재 반동 주문과 연사 횟수로 패턴의 수직·수평 계수를 구합니다. 다른 반동 주문으로 바뀌거나 마지막 호출 이후 `reset-delay` 이상 지나면 첫 발부터 시작합니다.
4. 잡음과 수평 치우침을 더하고 계수 범위를 제한한 뒤, 기본 강도·연사 증가·축별 배율을 곱합니다. 발당 크기 제한을 적용하고 여러 틱으로 나눠 예약합니다.
5. 공용 스케줄러가 같은 틱의 반동을 합쳐 플레이어당 최대 한 번 상대 회전을 보냅니다. 서버 조준 방향도 함께 갱신하며, 플레이어는 계속 마우스로 조준할 수 있습니다.

## `horizontal`은 각도가 아니라 배율

`n`은 0부터 시작하는 승인된 반동 호출 번호입니다. 패턴 선택 → 잡음 → 수평 bias → min/max 제한을 마친 계수를 각각 `v`, `h`라고 하면, 발당 제한을 적용하기 전 계산은 다음과 같습니다.

```text
강도 = recoil × (1 + growth × n)
수평 변화량(yaw)   = h × horizontal × 강도
수직 변화량(pitch) = -v × vertical × 강도
```

수평 양수는 오른쪽, 음수는 왼쪽입니다. 수직 계수 양수는 위쪽을 보도록 음수 pitch로 바꿉니다. `recoil: 0.5`, `vertical: 1.0`, `growth: 0`, `v = 1`이면 발당 위쪽 **0.5°**입니다. YAML 주석에 0.2도라고 적혀 있어도 실제 숫자 0.5를 사용합니다.

**수평 계수 `h`가 0이면 `horizontal: 1.5`처럼 배율을 높여도 수평 변화량은 0입니다.** `horizontal: 1.5` 자체가 발당 1.5°를 뜻하지 않습니다. `recoil: 0`은 두 축을 모두 끄고, `horizontal: 0`은 수평만 끕니다.

| 설정 | 역할과 주의점 |
| --- | --- |
| `recoil` | 양쪽 축에 곱하는 기본 강도 |
| `vertical`, `horizontal` | 각 축의 배율. 패턴 계수가 0이면 배율만 올려도 움직이지 않음 |
| `vertical-min/max`, `horizontal-min/max` | 각도 대신 **배율 적용 전 계수**의 범위. random에서는 추출 범위이고 모든 패턴에서는 최종 계수 제한으로도 사용 |
| `horizontal-bias` | 수평 계수에 더하는 값. 양수면 오른쪽으로, 음수면 왼쪽으로 치우침 |
| `pattern-randomness` | 계수에 더하는 독립 잡음. vertical 패턴에는 수평 잡음을 더하지 않음 |
| `growth` | 발마다 강도를 증가시킴. 0이면 연사해도 같은 강도이고 `recoil-steps` 수만큼 증가하지 않음 |
| `max-recoil` | 발당 yaw/pitch 합성 길이의 상한. 초과하면 두 축을 같은 비율로 줄이며, 누적 시점 각도 상한이 아님 |

## 패턴별 수평 반동

| `pattern` | 잡음·bias·범위 제한 전 동작 |
| --- | --- |
| `vertical` | 수직 계수 1, 수평 계수 0. 기본 bias와 범위에서는 **수평 반동이 없으며**, `horizontal`이나 `pattern-randomness`만 높여도 생기지 않음 |
| `valorant` | 수직은 누적 상승 각도 `valorant-max-rise`에서 제한. 수평은 중앙 기준 목표 위치의 차이로 계산하여 **중앙 → 오른쪽 → 중앙 → 왼쪽 → 중앙**으로 이동. 기본 첫 4발은 수평 0이며, 이는 이 프로젝트의 프리셋 규칙 |
| `random` | 각 축의 min/max 사이에서 매 발 독립적으로 계수를 추출. 첫 발부터 수평 추출이 가능하며, 항상 좌우가 번갈아 나오거나 모든 발이 눈에 띄게 움직인다는 보장은 없음 |
| `custom` | `custom-pattern`의 한 점을 한 발에 사용. 점의 `horizontal: 0`이면 그 점의 기본 수평은 0. `loop`는 반복, `hold`는 마지막 점 유지, `stop`은 목록이 끝난 뒤 두 축 모두 무반동 |

`vertical`에도 명시적인 `horizontal-bias` 또는 0을 포함하지 않는 수평 min/max를 설정하면 수평 변화가 생길 수 있습니다. 반대로 어떤 패턴이든 수평 min/max를 모두 0으로 두면 수평이 차단됩니다. `valorant`의 첫 4발 설명은 기본 `pattern-randomness: 0`, bias 0, 기본 범위 기준입니다.

`reset-delay: 400`에서 매 발 간격이 400ms 이상이면 계속 첫 발로 초기화됩니다. 이 상태의 기본 `valorant`에서는 `horizontal`을 높여도 좌우 흔들림 구간까지 진행하지 않습니다. 단발부터 수평 반동이 필요하면 `random`, 수평 값이 있는 `custom`, 또는 의도한 bias/잡음을 사용하세요.

## 내장 valorant의 상한과 좌우 중심

`valorant-max-rise`는 연사 한 번에 예약할 위쪽 반동의 합계 상한이며 기본값은 **15도**, 허용 범위는 0..90도입니다. **정해진 발 수가 지나면 중지하는 방식이 아닙니다.** 예를 들어 growth 0, 수직 계수·배율 1에서 recoil 1이면 15발, recoil 1.5면 10발에 15도에 도달합니다. 범위를 넘기는 마지막 발은 남은 각도만 적용합니다. 잡음이나 양수 vertical-min이 있어도 상한을 넘겨 계속 상승하지 않습니다.

상한은 서버의 절대 pitch나 마우스 입력을 제한하지 않습니다. 마우스를 아래로 내렸다고 새로운 상승 예산이 생기는 것도 아닙니다. `reset-delay` 이상 쉬거나 세션을 초기화하면 새 연사가 시작됩니다. 다른 패턴에는 이 옵션을 적용하지 않습니다.

수평에서는 sin 값을 회전량으로 계속 더하지 않고, **목표 위치의 이전·현재 차이**를 보냅니다. growth가 0이고 bias·잡음·클리핑이 없다면 중앙 기준 양쪽 정점은 약 `±2 × recoil × horizontal`입니다. growth가 있으면 강도 변화도 차분 계산에 반영해 중앙 통과 지점이 한쪽으로 밀리지 않게 합니다. 의도적으로 bias·비대칭 범위를 주거나 발당·틱당 제한에 걸리면 대칭이 달라질 수 있습니다.

## 실제 VALORANT와 공개 자료의 구분

이 애드온의 valorant는 독자적인 근사 프리셋입니다. 앞의 첫 4발 규칙이나 상승 상한은 Riot의 공통 무기 규칙을 복제한 값이 아닙니다. Riot은 무기별 수직 곡선과 확률적인 수평 방향 전환을 설명합니다. [공식 11.08 패치](https://playvalorant.com/en-us/news/game-updates/valorant-patch-notes-11-08/), [공식 6.11 패치](https://playvalorant.com/en-us/news/game-updates/valorant-patch-notes-6-11/).

비공식 [공개 데이터 API](https://valorant.gs/data/)는 게임 파일에서 추출한 무기별 곡선을 제공합니다. [추출 방법과 한계](https://valorant.gs/about/)에 따르면 특정 빌드의 데이터이며 실제 서비스의 핫픽스와 다를 수 있습니다. 곡선 값을 그대로 발당 카메라 회전량으로 더해도 되는지는 별도 검증이 필요합니다. 현재 애드온은 그 데이터를 가져와 적용하지 않습니다.

## 첫 발부터 수평을 적용하고 수직은 일정하게 유지하는 예시

```yaml
MyGun_Recoil:
  spell-class: "dev.magicrecoil.spells.RecoilSpell"
  helper-spell: true
  recoil: 0.5
  vertical: 1.0
  horizontal: 1.5
  pattern: random
  vertical-min: 1.0
  vertical-max: 1.0
  horizontal-min: -1.0
  horizontal-max: 1.0
  growth: 0.0
  recoil-steps: 2
  reset-delay: 400
  auto-return: false
  require-success-of: MyGun_Beam
```

이 예시는 기본 잡음·bias·발당 제한에서 **발당 위쪽 0.5°, 수평 -0.75°..+0.75°**입니다. 수평은 범위 내 무작위 값이며 ±0.75°가 매번 고정 적용되는 것은 아닙니다. 수직 min/max를 1로 맞춰 수직 계수를 고정합니다. 이 두 옵션 없이 random으로만 바꾸면 기본 수직 범위 0..2에서 추출하므로 위쪽 강도도 달라집니다. 수평 배율을 0.5로 낮추면 같은 조건에서 좌우 범위는 ±0.25°가 됩니다.

발사 목록은 `MyGun_Beam` → `MyGun_Recoil` 순서여야 하며, `require-success-of`에는 **실제로 호출하는 발사 주문**을 적습니다. Beam으로 발사하면서 예전 PP 주문 이름을 남기면 성공 기록이 없어 반동 전체가 거부됩니다. 반동 주문 이름만 바꾸거나 발사체의 `beam-horizontal-spread`를 바꾸는 것으로 시점 수평 반동을 켤 수는 없습니다. 탄퍼짐과 시점 반동은 별개의 설정입니다. 기존 재장전·버프 종료 중지 옵션도 실제 주문 이름으로 연결하세요.

## 부드러움·연사 중첩·초기화·복귀

- `recoil-steps`를 지정하면 `smoothness`보다 우선합니다. 생략하면 `1 + round(4 × smoothness)`틱으로 계산하며, 기본 smoothness 0.5는 3틱입니다.
- 한 발을 단순 균등 분할하지 않고 앞부분이 강한 가중치로 나눕니다. 2틱은 `2/3, 1/3`, 3틱은 `1/2, 1/3, 1/6`입니다. 위 예시의 pitch는 약 `-0.3333°, -0.1667°`이며 수평도 같은 비율로 나뉩니다.
- 첫 적용은 다음 스케줄러 틱입니다. 20 TPS에서 2틱은 약 100ms이고 TPS가 낮으면 늘어납니다. 이미 진행 중인 반동이 있으면 새 반동을 같은 미래 틱에 더합니다. 분할은 강도를 줄이거나 자동 복귀시키는 기능이 아닙니다.
- 정상 범위에서는 분할 전후 총량이 같습니다. 발당 `max-recoil`, 틱당 합성 45°, pitch의 절대 시야 범위 ±90° 제한에 걸리면 실제 적용량은 줄어듭니다. 정면 위·아래 한계에서는 수직이 잘려도 수평은 별도로 적용될 수 있습니다.
- `reset-delay`는 연사 패턴·증가율 초기화 간격입니다. 사격을 멈추면 예약된 반동은 끝까지 적용되며, 시간이 지났다는 이유만으로 시점이 되돌아가지는 않습니다. 간격 이후 새 발사가 들어오면 이전 잔여 반동을 버리고 첫 발부터 시작합니다.
- `auto-return: false`는 자동 복귀를 끕니다. true는 초기화 간격과 잔여 반동 종료 후 실제 적용량을 반대로 더합니다. 저장한 절대 시점으로 돌아가는 기능이 아니며 사용자의 마우스 보정까지 알 수 없어 과보정할 수 있습니다.
- 다른 반동 주문으로 전환, 슬롯·인벤토리 조작, 사망, 로그아웃, 텔레포트, 월드 이동, `/ms reload`, 명시적 중지는 남은 반동과 해당 상태를 정리합니다. `stop-on-spells`는 지정 주문의 시도 시점에, `stop-on-buff-end`는 지정 버프 종료 시점에 남은 반동을 취소합니다.

설정은 전역 파일 대신 해당 총기의 반동 주문 아래에 적습니다. YAML 수정은 `/ms reload` 후 콘솔 오류를 확인하고, JAR 교체는 서버 재시작으로 적용합니다. 전체 범위·검증 규칙은 [설정 문서](configuration.md), 발사 성공 이벤트와 중지 연결은 [연동 문서](integration.md)를 참고하세요.

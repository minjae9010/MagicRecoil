# 버전 호환 안내

[한국어 문서](README.md) · [English](../en/compatibility.md)

최소 기준은 **Paper 1.21.4 / MagicSpells 4.0-Beta-17**입니다. 버전 완전 일치 제한을 제거했습니다. 이후 MagicSpells 베타·RC·정식 버전도 필요한 바이너리 API가 호환되면 허용합니다. 최소 버전 이상 서버에서는 지원되는 네이티브 회전 메서드가 있으면 동작합니다. 미래의 API 변경까지 무조건 호환된다는 의미는 아닙니다.

## 자동 선택 방식

시작 시 MagicSpells의 외부 클래스 로더, 주문 생성자·시전 계약, 설정 조회, 이벤트 메서드, 필요한 열거형 값을 확인합니다. 호환되지 않으면 주문 로더 등록 전에 원인을 출력합니다.

Paper 어댑터는 Mojang 매핑의 플레이어 핸들, 연결 상태, 현재 각도, 회전 메서드를 한 번 찾아 저장합니다. `forceSetRotation(float, boolean, float, boolean)`이 있으면 상대 yaw/pitch를 사용합니다. 이전 서버에서는 현재 서버 조준값에 변화량을 더해 `forceSetRotation(float, float)` 절대 회전 경로를 사용합니다. 두 경로 모두 서버 조준값을 갱신하고 회전 전용 패킷을 보내며, 위치를 텔레포트하지 않습니다. 절대 회전은 패킷 전송 중 마우스 입력을 덮어쓸 수 있으며 시작 경고와 `/magicrecoil status`에 해당 모드가 표시됩니다.

공용 서버 스레드를 전제로 하므로 Folia는 지원하지 않습니다. 버전 변환, 수정 배포본, 안티치트, 다른 시점 플러그인 조합은 별도 검증이 필요합니다. 시험한 1.21.x 조합은 Java 21, 26.2 조합은 Java 25를 사용했습니다. 새 MagicSpells 자체의 Java·서버 최소 버전도 충족해야 합니다.

## 2026-11-15 검증 결과

Paper 1.21.4와 Beta 17 API로 컴파일한 동일한 애드온 JAR을 세 격리 서버에서 사용했습니다.

| Paper | MagicSpells | Java | 결과 |
| --- | --- | --- | --- |
| 1.21.4 빌드 232 | 4.0-Beta-17 | 21 | 시작·주문·상태·리로드 및 3° 반동 두 번 통과. 절대 회전 패킷 6개, 위치 패킷은 최초 접속 1개뿐. |
| 1.21.11 빌드 132 | 4.0-Beta-18 | 21 | 같은 항목 통과. 상대 회전 패킷 6개, 위치 패킷은 최초 접속 1개뿐. |
| 26.2 빌드 135 | 4.0-Beta-19 | 25 | 시작·주문 로딩·상태·리로드 통과. 사용 가능한 테스트 클라이언트에 26.2 지원이 없어 실제 접속 반동은 미검증. |

프로토콜 검증은 화면 렌더링과 실제 마우스 없이 수행했습니다. 사람이 느끼는 조작감, 지연·안티치트 조합, 모든 중간 서버 버전을 인증한 것은 아닙니다. 기존 GIF와 [테스트 문서](testing.md)의 상세 수치는 1.21.11/Beta 18에 대한 과거 검증 기록입니다.

자동 테스트는 숫자 기반 베타 순서, 최소 버전 거부, 실제 MagicSpells API, 두 회전 메서드, pitch·틱 제한, 연결 끊김·잘못된 각도, 비동기 호출, 네이티브 실패와 기존 반동 로직을 검사합니다. CI는 Linux/Windows Beta 17 기준과 Linux Beta 18/19 API를 빌드합니다. Java 25 대응 Mockito는 테스트 전용입니다.

## 조준·발사 기능과 통합

`0.2.0-alpha.2` 소스 빌드는 `0.2.0-alpha.1`의 조준·우클릭 버퍼 사격·Slowness 줌을 유지합니다. 기존 abilities 패킷 줌도 1.21.11 클래스에 고정하지 않고 API를 탐지한 뒤 현재 abilities를 복사합니다. 전송 테스트는 비행 플래그, 실제 서버 상태 보존, 변경된 최신 값의 복원을 확인합니다.

2026-11-16 통합 빌드가 자동 테스트 161개와 위 세 서버의 시작·리로드 검증을 통과했습니다. 1.21.4와 1.21.11에서는 리로드 전후 반동 두 번을 다시 확인했으며, 최초 접속 뒤 위치 패킷 없이 회전 패킷만 발생했습니다.

선택적 `NATIVE_USE`에는 Paper의 `USE_EFFECTS` 컴포넌트 API가 필요합니다. 없으면 해당 총기 바인딩을 거부하고 `BUFFERED_CLICK` 설정 안내를 출력합니다. 버퍼·반복 클릭 발사와 반동은 계속 사용할 수 있습니다. 이전 프로토콜에 없는 아이템 동작을 추가하지 않습니다.

## 빌드와 재검증

기본 `./gradlew build runtimeProbeJar`는 가장 오래된 지원 API를 사용하며 Java 21 바이트코드를 만듭니다. 서버 개발 번들과 실행용 ProtocolLib은 필요 없습니다. 공식 Beta 17/18/19 JAR은 SHA-256으로 고정합니다.

```sh
./gradlew build runtimeProbeJar -PmagicSpellsVersion=4.0-Beta-18 -PpaperVersion=1.21.11-R0.1-SNAPSHOT
# JDK 25에서 API를 검증합니다. 결과 클래스 형식은 Java 21입니다.
./gradlew build runtimeProbeJar -PmagicSpellsVersion=4.0-Beta-19 -PcompilerJava=25
```

PowerShell에서는 `'-PmagicSpellsVersion=4.0-Beta-19'`처럼 속성 인자마다 따옴표를 사용하세요. 다른 공식 배포본은 `-PmagicSpellsSha256=<검증한-sha256>`도 전달합니다. 빌드 옵션을 바꾸어도 실행 최소 버전은 바뀌지 않습니다. 서버와 MagicSpells 자체도 서로 호환되어야 합니다. 애드온 최소 기준이 Beta 19를 구버전 서버에 설치해도 된다는 의미는 아닙니다.

[서버 검증용 구성](../../tests/runtime/README.md)의 `RECOIL_TEST_VERSION`, `RECOIL_TEST_PORT`를 맞춰 사용하세요. 발사 성공·실패, 중지 훅, pitch 제한, 리로드·새 주문, 상태 정리를 반복하고 [수동 검수](testing.md)도 수행합니다.

공식 버전·소스 링크는 [영어 문서의 근거](../en/compatibility.md#upstream-evidence)에 모았습니다.

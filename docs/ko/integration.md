## 총기 동작을 유지하고 반동만 교체하기

반동 구성 요소는 탄약 감소, 발사체 생성, 데미지, 재장전을 구현하지 않습니다. 선택 AutoFireSpell은 우클릭 입력과 기존 발사 처리 전체의 호출 주기를 관리하며 탄약·발사체·피해·재장전 로직은 MagicSpells 설정에 남깁니다. 기존 설정에서 **한 발이 성공적으로 발사되는 분기**와 탄약·쿨다운·재장전·ON/OFF 조건을 먼저 찾습니다.

기존 반동 주문의 클래스와 반동 설정만 교체합니다. RotateSpell 전용 `rotation-pitch`, `rotation-yaw`, `affect-pitch`, `face`, 타깃 선택 설정은 그대로 가져오지 않습니다. RecoilSpell은 항상 **플레이어 시전자**에게 적용됩니다. 기존에 필요했던 일반 MagicSpells 조건과 수정자는 유지합니다.

```yaml
Weapon_AR_Recoil:
  spell-class: "dev.magicrecoil.spells.RecoilSpell"
  helper-spell: true
  recoil: 2.5
  require-success-of: Weapon_AR_Projectile
  stop-on-buff-end: [Weapon_AR_FiringBuff]
```

`Weapon_AR_*`는 범용 영어 예시 이름입니다. 기존 총기 구성에 맞춰 정의와 모든 참조를 함께 연결하세요. 반동 블록 이름만 바꾸면 발사 루프는 이전 이름을 계속 참조합니다.

`Weapon_AR_FireLoop`의 기존 성공 분기에서는 다음 순서를 유지합니다.

```yaml
spells:
  - Weapon_AR_Projectile
  - Weapon_AR_Recoil
```

이것은 전체 주문을 대체하는 YAML이 아닌 **일부분**입니다. 원본 파일이 제공되지 않아 실제 탄약 검사, 재장전 주문 이름, 발사체의 성공 판정, 버프 생명주기를 분석하지 못했습니다. [범용 총기 예시](../../examples/weapon-integration.yml)는 반동 블록 교체용으로 검토해야 합니다.

## 발사 성공 확인이 필요한 이유

Beta 18의 MultiSpell은 앞 하위 주문이 실패해도 뒤 주문을 계속 실행할 수 있습니다. 발사체 다음에 반동을 적는 것만으로 실패 시 반동이 차단되지는 않습니다.

`require-success-of`를 지정하면 해당 주문의 SpellCastEvent와 SpellCastedEvent를 확인합니다. 새 시도가 발생하면 이전 성공 기록을 지웁니다. 상태가 `NORMAL`이고 후처리가 `ALREADY_HANDLED`, `DELAYED`가 아닌 완료만 성공으로 기록합니다. 반동은 같은 Bukkit 틱에서 이 기록을 한 번만 소비합니다. 실패, 중복 호출, 이전 틱 기록, 다른 주문 기록은 거부합니다.

플레이어마다 가장 최근 기록 하나만 보관하므로 발사체/반동 쌍을 같은 틱에 연속 호출하세요. 서로 다른 두 반동 주문이 같은 발사 성공 기록을 함께 사용하면 안 됩니다.

### 호출 방식별 주의점

- **Partial**: Beta 18의 기본 하위 주문 호출 방식입니다. 이벤트는 발생하지만 일반 비용·쿨다운 검사는 우회합니다. 상위 발사 분기의 기존 탄약 검사를 유지해야 합니다. 성공 이벤트는 탄약 검사를 실제 수행했다는 증거가 아닙니다.
- **Full/hard**: 일반 시전 과정을 수행하지만 비용이나 기존 동작이 달라질 수 있습니다. 반동 연결만을 위해 무작정 변경하지 마세요.
- **Direct**: `cast()`를 직접 호출하여 필요한 이벤트가 없습니다. 성공 확인 옵션이 있으면 반동은 실행되지 않습니다. 이미 보장된 성공 분기에서 호출하거나 원본 동작을 검토한 뒤 이벤트를 발생시키는 방식으로 연결하세요.
- **Delayed**: 예약 시점에는 완료 성공 기록이 없습니다. 실제 발사 완료 틱에 반동이 연결되어야 합니다.
- 성공 기록은 주문이 보고한 결과를 신뢰합니다. 실제 탄환 생성이나 명중 여부를 검사하는 기능은 아닙니다. 일부 주문은 아무것도 생성하지 않고 정상 처리로 반환할 수 있습니다.
- `require-success-of`가 비어 있는 최소 예시는 수동 시험용으로도 쓸 수 있지만 실제 총기에서는 호출 분기가 발사 성공을 보장해야 합니다.

탄약 부족과 재장전 상태는 원래 총기의 발사 자체를 막아야 합니다. 애드온은 임의의 변수 이름, 아이템 설명, 탄약 저장 방식, 버프 의미를 추측하지 않습니다.

## 재장전과 중지 연결

반동 주문의 `stop-on-spells`에 **실제 재장전 시작 주문 이름**을 넣습니다. 시도 시점에 취소하므로 나중에 실패하는 재장전 시도도 남은 반동을 지웁니다. `stop-on-buff-end`는 해당 발사 버프가 플레이어에게서 끝날 때 취소합니다. 원본 버프의 대상이 시전자와 같은지 확인하세요.

설정된 중지 이벤트는 성공 기록을 무효화하고 해당 틱의 이후 반동도 거부합니다. 발사체 → 재장전 시작 → 반동 순서도 처리합니다. 다음 틱 이후에는 원래 총기의 재장전 상태 검사가 계속 발사를 막아야 합니다.

이벤트 없는 direct 경로라면 다음 보조 주문을 기존 재장전 시작 지점에 호출합니다.

```yaml
Weapon_StopRecoil:
  spell-class: "dev.magicrecoil.spells.StopRecoilSpell"
  helper-spell: true
```

이 주문은 남은 반동과 성공 기록을 제거하지만 시점을 원래 방향으로 돌리거나 이후 발사를 차단하지는 않습니다. 재장전 중 발사 방지는 기존 로직이 담당합니다. 같은 슬롯의 무기 아이템을 이벤트 없이 교체하는 경우에도 사용할 수 있습니다.

핫바 전환, 손 교환, 아이템 버리기, 인벤토리 클릭·드래그, 사망, 로그아웃, 텔레포트, 월드 전환은 자동 초기화합니다. 인벤토리는 보수적으로 처리하여 다른 칸의 정상 클릭도 연사를 끊습니다. 서로 다른 반동 주문 이름도 세션을 교체합니다.

## 탄환 방향과 호출 순서

현재 탄환은 새 반동이 예약되기 전의 서버 조준 방향으로 발사됩니다. 반동은 다음 스케줄러 틱부터 적용됩니다. 후속 탄환은 변경된 서버 회전값을 사용하되 네트워크 지연과 발사체 설정의 방향 저장 방식에 영향을 받습니다.

반복 버프가 처음의 `SpellData.location`을 저장해서 계속 재사용하면 현재 시점이 바뀌어도 탄환 방향은 유지될 수 있습니다. 실제 발사체의 위치·방향 전달 옵션을 확인하세요. MagicRecoil은 다른 주문이 저장한 데이터를 강제로 바꾸지 않습니다.

같은 서버 틱에 여러 발을 쏘면 새 반동이 적용되기 전 방향을 공유하고, 반동은 버퍼에서 합쳐집니다. 산탄총은 펠릿 수만큼 반동을 중복 호출하지 않도록 구성하세요.

## `/ms reload` 동작

Beta 18은 기존 주문을 정리하고 외부 클래스 로더 목록을 비운 뒤 로딩 이벤트를 발생시키고 YAML 주문을 다시 만듭니다. MagicRecoil은 다음과 같이 대응합니다.

1. 기존 RecoilSpell의 `turnOff()`에서 해당 주문의 세션을 제거합니다.
2. MagicSpellsLoadingEvent에서 모든 반동·성공 기록을 정리하고 클래스 로더를 다시 등록합니다.
3. MagicSpellsLoadedEvent에서 발사 성공 확인 대상 목록을 다시 구성합니다.

수치 변경과 새 주문 추가는 `/ms reload`로 적용할 수 있습니다. Java 클래스 교체는 지원하지 않으므로 JAR 변경은 전체 서버 재시작으로 적용합니다. 설정 오류로 일부 주문이 로딩되지 않을 수 있으므로 리로드 뒤 콘솔을 확인하세요.

## 문제 해결

| 증상 | 확인할 사항 |
| --- | --- |
| missing/malformed class | 전체 클래스명, plugins에 JAR 한 개만 설치, 지원 버전, 시작 오류 |
| 최소 예시는 되지만 총기에서는 안 됨 | 성공 확인 이름, 같은 틱의 호출 순서, direct/delayed, 실제 반환 결과 |
| 탄약 없는데 반동 발생 | 상위 탄약 검사, partial의 비용 검사 우회, 성공 확인 옵션 |
| 재장전 중 남은 반동 | 실제 시작 주문 이름, 이벤트 유무, 명시적 중지 주문 |
| 너무 느리거나 떠 있는 느낌 | recoil-steps를 2~3으로 낮추고 TPS 확인 |
| 수평 반동이 없음 | 기본 vertical은 수평 계수가 0. horizontal만 높이지 말고 패턴 확인. 기본 valorant은 첫 4발이 수평 0이며 reset-delay 이상 간격이면 계속 초기화됨. 수평 min/max가 모두 0인지도 확인 |
| 수평 반동 과다 | horizontal, bias, randomness와 min/max 계수 확인 |
| 같은 슬롯 무기 교체가 안 잡힘 | 다른 반동 주문 이름 또는 StopRecoilSpell 사용 |
| 탄환이 시점 변경을 무시함 | 반복 주문의 저장된 원점·방향, 실제 탄도 시험 |
| 다른 플러그인과 화면 충돌 | 시점/텔레포트/안티치트 플러그인을 하나씩 조합해 재현 |

## Buff 총기에 조준 추가

[조준과 기존 Buff 연동](aim-and-input.md#기존-buff-총기와-반동-연동), [파이먼 병합 예제](../../examples/aim-paimon.yml)를 참고하세요. 새 조작에서는 조준을 좌클릭에 배정하고 연사는 AutoFireSpell의 use-item으로 등록하며 기존 발사 성공 경로 전체를 보존하세요. 이벤트가 없는 재장전에는 StopAimSpell·StopAutoFireSpell을 추가하며 PassiveSpell 발사를 Beam 직접 호출로 대체하지 않습니다.

## 우클릭 연사 연동

선택 AutoFireSpell은 우클릭 입력과 발사 처리 주문의 호출 주기만 관리합니다. 탄약·발사체·데미지·재장전은 기존 MagicSpells 주문에 남깁니다. [전체 입력 설정](aim-and-input.md#우클릭-자동-사격)과 [파이먼 연사 예제](../../examples/right-click-paimon.yml)를 참고하세요. 새 조작에서는 좌클릭을 조준에 배정하고 기존 Buff의 마우스 바인딩을 제거합니다. PassiveSpell의 성공 처리 전체를 일반 동기 발사 진입점으로 분리하여 호출하며 두 연사 루프를 동시에 실행하지 마세요. 이벤트 없는 재장전에는 StopAutoFireSpell을 맨 앞에 추가합니다.
